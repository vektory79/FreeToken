# Route affinity на конкретный запрос (per-request, вариант B)

## Goal

Дать вызывать route affinity значением запроса (поле `route_affinity` в
OpenAI/Anthropic/Responses-запросах), по образцу `temperature`: значение
из запроса снапится к ближайшему значению лестницы, и декод-шаг реплеит
заранее захваченный CUDA-граф этого (bs, affinity). Серверный дефолт
(`--route-affinity`) остаётся поведением по умолчанию; полная реализация
не меняет механику бонуса (Maya-семантика Maya: меняется выбор, не веса).

## Мотивация и фон

- Route affinity - серверный флаг на старте (`--route-affinity`, дефолт
  0.0; гейт качества закрыт вердиктом GO-CLI, победитель 0.3,
  [../route-affinity/VERDICT.md](../route-affinity/VERDICT.md)). Значение
  запечено в ядро как constexpr `ROUTE_AFFINITY`
  (`kernel/triton/moe_router.py`, JIT-вариант на значение) и в
  захваченные CUDA-графы; резидент-маска, напротив, динамическая
  (читается из offload-кэша на каждом реплее).
- Температура - per-request, потому что применяется к сэмплу логитов
  после форварда. Affinity - часть форварда, поэтому путь к per-request
  один: захватить граф на каждое значение лестницы и выбирать граф на
  шаге по значению батча.
- Экономика первого замера: base 22.54 tok/s / hit 35.7%; 0.2 -> 38.55
  tok/s / hit 73.6% (цена качества - см. VERDICT). Измерения в
  [../route-affinity/RESULT.md](../route-affinity/RESULT.md).
- Owner-решения (2026-11-15): снап значения запроса к ближайшему значению
  лестницы (ties - меньшее); при разнобое значений в батче fallback 0.0
  + однократный warn; некаптурированных значений не остаётся, eager
  fallback по значению не нужен.

## Scope

**Входит:**

- Ф0 (CPU): полная реализация цепочки (см. Specification) + CPU-тесты
  логики снапа/разнобоя/валидации; boot-строка resolved-конфига.
- Ф1 (GPU, cloud-окно): бут с лестницей {0.0, 0.3} и приёмочные пробы
  per-request: запрос route_affinity=0.3 -> hit/ток/с соответствуют
  флагу; чередование 0.0 <-> 0.3 между запросами -> оба значения
  работают без рекапчура; два одновременных запроса с разными
  значениями -> fallback 0.0 + warn.
- Ф2: замер цены лестницы (VRAM/бут): A/B бутов с лестницей из 1 и из 3
  значений (free GPU memory до/после захвата, время бута). Числа
  записать в артефакты и [verdict-файл кейса](VERDICT.md).

**Не входит:** разрезание декод-батчей по группам affinity при
`--max-running-requests > 1` (честный per-request в смешанном батче -
семантически невозможен одним форвардом: бонус применяется к fused-topk
на слой, маска резидентности общая, `models/glm5_next/moe.py:65-70`);
коммиты без явной команды владельца; изменение механики бонуса и
дефолта.

## Specification

Точки правок (по файлам, все места сверены с кодом 2026-11-15):

1. **CLI** (`server/args.py`): новый флаг `--route-affinity-ladder`
   (comma-separated float, дефолт - только серверное значение из
   `--route-affinity`). На буте лестница = дедупликация
   `лестница ∪ {server_default}`, значения >= 0.
2. **EngineConfig / инъекция** (`engine/config.py`, `engine/engine.py`):
   `route_affinity_ladder: list[float]`; инъекция в ModelConfig рядом
   с `route_affinity` (engine.py ~2432); resolved-строка отражает
   лестницу.
3. **Модель** (`models/glm5_next/moe.py`): у топового класса модели
   `set_route_affinity(value)`: перебирает MoE-слои и переприсваивает
   `block.route_affinity`. Блоки и так читают атрибут в `_route` при
   каждом eager-форварде; вызов сеттера до захвата графа запекает
   значение в граф. Сеттер - метод модели, движок зовёт его через
   hook (`hasattr`-проверка), другие модели не затронуты.
4. **GraphRunner** (`engine/graph.py`): параметры `affinity_values`
   (лестница) и `affinity_hook` (сеттер); `_capture_graphs` захватывает
   для каждого bs все значения лестницы (внутренний цикл по значению;
   сброс offload-кэша повторять на каждом захвате, как уже сделано на
   границе bs); `graph_map` ключ `(padded_bs, affinity)`. Значения,
   отличные от дефолта, в graceful-дисейбл: если лестницы нет -
   поведение в точности сегодняшнее. `spec.capture_graphs` и
   spec/mtp-пропозеры не получают hook (чертновик без спека).
5. **replay/выбор графа**: `replay` берёт граф
   `graph_map[(padded, batch.route_affinity)]`; `can_use_cuda_graph`
   добавляет проверку наличия ключа. Prefill - инертен (affinity
   влияет только на декод; materialize очищает строки слотов каждый
   чанк).
6. **Eager-путь** (`engine/engine.py`, `forward_logits`): когда граф
   не выбран (bs > max_graph_bs, графы отключены, verify), движок
   перед `self.model.forward()` применяет hook по батчевому
   affinity. Декод вне графа с affinity == дефолту не должен отличаться
   от сегодняшнего (значение уже в блоках).
7. **Req/Batch** (`core.py`): `Req.route_affinity: float | None = None`
   (None = серверный дефолт резолвится движком);
   `Batch.route_affinity: float = 0.0`, выставляется планировщиком при
   сборке декод-батча по правилу снапа (ниже). Думние (пэддинг) строки
   бонус не портит - их выход отбрасывается.
8. **Правило снапа** (движок, единая точка): резолв
   `req.route_affinity None -> EngineConfig.route_affinity`; снап к
   ближайшему значению лестницы (min |delta|, ties - меньшее); если
   все decode-запросы батча после снапа согласны -> это значение
   батча; иначе 0.0 + однократный warn в лог.
9. **API** (`server/api_models.py`, `anthropic_models.py`,
   `responses_api.py`, `openai_api.py`, `generation.py`):
   `route_affinity: float | None = None` по образцу `temperature`
   (pattern `pick()` в generation.py ~214/241); валидация 0 <= v,
   конечное; снап делает движок, сервер передаёт сырое значение.
10. **Docs**: `docs/cli.md` - строка флага лестницы; описание поля
    запроса в API-доках; семантика батча (fallback 0.0) упомянуть.

Ответы на вопросные случаи (зафиксировано владельцем 2026-11-15):

- **0.0 в лестнице**: (bs, 0.0) - это сегодняшние дефолт-графы (ветка
  `ROUTE_AFFINITY > 0` в ядре компилируется наружу, JIT-вариант 0.0
  уже в кэше ядер). Дедупликация делает случай прозрачным.
- **Чередование значений от запроса к запросу**: affinity читается на
  каждом декод-шаге; шаг 0.05 реплеит граф 0.05, шаг 0.3 - граф 0.3.
  Оба графа захвачены на буте, переключение мгновенное, без рекапчура
  и порчи качества (веса unbiased в обоих случаях).
- **`--max-running-requests > 1`**: батч с одинаковым снап-значением
  у всех запросов работает как одно значение; при разнобое - fallback
  0.0 + warn (см. "Не входит"). На bs=1 (локальная LLM) это чистый
  per-request.

## Gotchas

- Affinity запекается в граф на этапе захвата: между захватами разных
  значений обязателен вызов hook (сеттера модели) - захват для bs уже
  сбрасывает offload-кэш (`_reset_moe_offload_cache` в
  `_capture_graphs`), при внутреннем цикле по значениям сброс
  повторять на каждом значении.
- Python-ветка `if self.route_affinity > 0` в `_route` (moe.py:65) -
  логика построения резидент-маски на eager-форварде; граф 0.0 ветку
  не строит вовсе.
- Веса `activated` всегда unbiased (семантика Maya, moe_router.py:102);
  ломать нельзя - меняется только выбор.
- Спекулятивный декод: verify-графы захватываются другим кодом
  (spec.capture_graphs) и hook не получают; в прод-конфиге GGUF
  hybrid спека отключена, ограничение задокументировать.
- Boot-время растёт как |bs_list| x |лестница| захватов; цену
  подтвердить Ф2 прежде чем дефолтить широкую лестницу.
- Коммиты - только по явной команде владельца; диффы держать в
  рабочем дереве.

## Примечание

Правило кампаний соблюдено: реализация отделяется от измерений (Ф0
CPU, Ф1/Ф2 - cloud-окно по VRAM-протоколу). Качественный гейт значений
уже закрыт вердиктом маршрута ([../route-affinity/VERDICT.md](../route-affinity/VERDICT.md)),
поэтому эта кампания - чисто реализационная, качества не дегейтит:
снап не меняет набор значений против гейта.
