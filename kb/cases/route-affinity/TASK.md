# Полный гейт route affinity (качество прежде скорости)

## Goal

Решить по заранее утверждённым порогам, заслуживает ли route affinity
(Maya-механика: бонус резидентным экспертам в скор выбора маршрутизатора)
CLI-флага и дефолта в прод: лестница значений 0-0.3 с повторами для скорости
и слепой парный суд качества ответов против базы. Качество - первичная
метрика гейта: рычаг меняет сами ответы (уже при 0.05 сместился весь
роутинг), скорость без качества не принимается.

## Мотивация и фон

- Первый замер ([RESULT.md](RESULT.md), 2026-11-15, по одной руке на
  значение): base 22.54 tok/s / hit 35.7%; 0.05 -> 26.34 (+16.9%) / 48.9%;
  0.2 -> 38.55 (+71.0%) / 73.6%. Оценка покрытия при 0.2 ~81% - на уровне
  ПОТОЛКА офлайн-кривой слотов (82%,
  [../offline-coverage-curve/VERDICT.md](../offline-coverage-curve/VERDICT.md)):
  affinity бьёт все ёмкостные рычаги, потому что меняет запрос, а не ёмкость.
- Якорь Maya: +7-11% при 0.05, +22-25% при 0.2 - их модели и стек, числа не
  переносить.
- Цена: проза меняется 4/4 уже при 0.05. Короткая батарея первого замера
  качество не вердицирует - для этого и нужен полный гейт.
- Правило кампаний 2026-09-26: ёмкостные/роутинговые рычаги проходят оценку
  до реализации; здесь реализация уже есть (env-гейт), гейт решает её судьбу.

## Scope

**Входит:**

- Ф0 (CPU-префлайт): env-гейт на месте (`grep FREETOKEN_ROUTE_AFFINITY` в
  обоих файлах; если мердж/ребейз потерял - восстановить по спеке в
  [RESULT.md](RESULT.md)); харнесс компилируется; VRAM свободна, census
  `pgrep -af '[f]t serve'` чист; расширение раннера (см. Спецификацию):
  батарея из файла, сохранение полного текста 768-продолжения, NIAH-проба.
- Ф1 (скоростная лестница, GPU, сериально): значения {0, 0.05, 0.1, 0.15,
  0.2, 0.3} x 2 бута каждый + 3-й бут победителя (<= 15 бутов, ~1.5 ч).
  Метрики: steady tok/s (SSE-дельты), p50 мс/шаг, hit-строки "MoE decode".
- Ф2 (качество, на тех же бутах): слепой парный суд (база vs значение)
  по всем текстам: арифметика-пояснения, батарея 24 промптов, NIAH,
  проза, полный текст 768-продолжения. Плюс одна мульти-turn проба
  (5 ходов, резидентность живёт между запросами).
- Ф3: сводная таблица медиан, гейт-вердикт, VERDICT.md в этот каталог,
  зеркало харнесса в kb, обновление памяти.

**Не входит:** CLI-флаг и дефолт (решение владельца ПОСЛЕ гейта); batch > 1;
повторное кернельное улучшение; KV-стриминг (закрыт NO-GO, см. VERDICT
выше). Коммиты - только по явной просьбе владельца.

## Specification

- **Бут и рука**: метод run_arm.py из
  [../../harness/route-affinity/](../../harness/route-affinity/README.md):
  boot точного прод-конфига (графы, НЕ eager; FREETOKEN_DECODE_RESEARCH не
  выставлять), fill 64k, radix-reuse greedy декод 768 c ignore_eos, затем
  батарея. Порядок руки: декод-метрики ПЕРЕД батареей (hit-строки чище).
- **Батарея руки** (всё greedy, уникальные nonce где radix может отдать
  старое): (а) 6 арифметических (авто-чек; budgets >= 96; сравнение
  content + reasoning_content - готча reasoning-парсера); (б) батарея
  24 промптов кампании GGUF (искать в .tasks/gguf-glm5next-hybrid/; если
  файл не найден - собрать 20 RU/EN промптов заново и зафиксировать в
  каталоге кейса); (в) NIAH-проба: 20 запросов ключ-значение на глубинах
  ~40-60k (методика kv-quant-ab, 60/60 у fp8 - здесь достаточно порога
  относительно базы); (г) 4 прозаических; (д) полный текст 768-продолжения
  филлера. Ответы сохраняются дословно в arm_*.json.
- **Суд**: слепой парный, base vs X для каждого не-нулевого значения;
  порядок A/B в паре рандомный, метки снимаются после вердикта судьи;
  рубрика: фактическая корректность, связность, следование инструкции;
  исходы: base-лучше / tie / X-лучше; tie засчитывается БАЗЕ
  (консервативно). Судья - LLM сессии (облачная модель владельца); промпты
  судьи и ответы сохраняются в артефакты; 10% пар пересуждаются повторно
  (самосогласованность).
- **Пороги гейта (утверждаются ДО Ф1; любое изменение - запись в VERDICT)**:
  - Качество значения X: доля пар "не хуже базы" (tie=база) >= 85% по всем
    текстам суда AND 0 новых фактических ошибок на промптах с проверяемым
    ответом AND NIAH не ниже базы - 2 п.п.
  - Скорость-порог полезности: медиана tok/s значения >= base + 10%
    (ниже - ручка не окупает сложность и риск).
  - Победитель: максимум медианы tok/s среди значений, прошедших качество.
  - Плато-правило: если большее значение даёт скорость в пределах шума
    (~7%) меньшего - берётся меньшее (качество).
  - Вердикт: GO-CLI (победитель прошёл оба порога) / NO-GO (нет значения,
    прошедшего качество при >= +10%) / OWNER (качество ок, скорость в
    7-10%). Независимо от вердикта - диффы остаются env-гейтами до явной
    команды владельца.
- **Приоры из первого замера** (не якоря, а гипотезы для сравнения):
  22.54 / 26.34 / 38.55 tok/s; hit 35.7 / 48.9 / 73.6%; ожидание - плато
  скорости между 0.2 и 0.3 при растущей цене качества.

## Gotchas первого замера (обязательны к учёту)

- GLM reasoning parser: на коротких non-stream бюджетах `message.content`
  ПУСТОЙ - сравнивать content + reasoning_content; арифметике бюджет >= 96;
  arith_bin (156 -> двоичная) constant-FAIL при 96 - встроенный контроль
  одинаковых условий между руками, не деградация.
- ignore_eos обязателен на 768-декоде: без него EOS резал до 545.
- Замер - в прод-графах; eager и FREETOKEN_DECODE_RESEARCH не нужны.
- --moe-collect-stats обязателен (hit-строки "MoE decode"; периодический
  reset - норма, метрика - по интервалам).
- Сериальность: один сервер за раз; census `pgrep -af '[f]t serve'`;
  readiness - реальным chat-запросом, не дешёвым эндпоинтом.
- Правило VRAM: перед бутами владелец переключается на облачную LLM;
  после - сообщить об освобождении.
- Диффы env-гейта не закоммичены: после любого мерджа проверить
  `grep -c FREETOKEN_ROUTE_AFFINITY` в models/glm5_next/moe.py и
  kernel/triton/moe_router.py; спека восстановления - в [RESULT.md](RESULT.md).

## Примечание

Affinity меняет роутинг, а роутинг - ответы. Даже "выигравший" значение
внедряется как OPT-IN ручка с документированной ценой, не как безмолвный
дефолт: дефолт - решение владельца по материалам Ф2. Числа Maya - их
машины; наши пороги утверждаются в этом файле до старта Ф1.
