# Fails-before тесты: эмпирическое доказательство новизны

Требование репозитория: багфикс приходит с тестом, который красный ДО правки и
зелёный после. Проблема: тест, написанный по коду, часто проходит и без правки
(регрессионный щит вместо fails-before). Волна P2 отработала эмпирический
протокол, который доказывает красность прогоном, а не рассуждением.

## Протокол

1. Напиши тесты против брифа (до правки прод-кода или параллельно).
2. Прогони их на НЕправленом коде - это и есть проверка fails-before.
   Практический приём на незакоммиченной волне: `git stash` правок прод-кода,
   зафиксировать md5 восстановленного файла для контроля, прогнать тесты,
   вернуть правки (повторный md5-контроль). Тесты должны быть красными.
3. Тесты, которые уже проходят без правки, классифицируй:
   - проверяют существующее поведение -> оставь как **регрессионный щит**,
     но их новизна не считается fails-before;
   - для щита из нескольких точек правки полезен **single-revert probe**:
     откатываешь ОДНУ правку из композиции - вердикт щита должен измениться.
     Если щит не меняет вердикт ни при каком одиночном откате, он не защищает
     ни одну из них.
4. После правки: все тесты зелёные; красные-до остаются задокументированными
   доказательством fails-before (номер прогона / вывод в отчёте волны).

## Ловушки pytest, пойманные в волне P2

- **caplog не видит non-propagating module logger.** `caplog` в pytest не
  ловит записи логгера модуля с нестандартной конфигурацией хендлеров
  (наблюдение волны P2 на модульном логгере session_tier). Симптом: тест,
  проверяющий появление лог-строки, молча не видит её. Решение: свой capture -
  фикстура вешает handler прямо на нужный логгер и собирает записи.
- **Тест-хелпер должен зеркалить прод-дисциплину.** Если прод-код пишет
  файл через tmp + fsync + rename + fsync каталога, хелпер обязан повторять
  этот порядок, а не писать файл напрямую: иначе тест проверяет другой
  инвариант (например, про прочность rename-семантики), которого в проде нет.

## Когда применять

- Любой багфикс (требование CONTRIBUTING) - шаги 1-4 обязательны.
- Новые тесты в волнах с правкой поведения: отделяй fails-before от щита,
  чтобы отчёт волны не завышал покрытие.
- Волны на незакоммиченном состоянии: stash+md5-приём - единственный способ
  получить "красный ДО", не теряя правок.
