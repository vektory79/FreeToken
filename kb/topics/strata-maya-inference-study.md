# Опыт Strata и Project Maya: что переносимо в GGUF-hybrid

**Вердикт (читайте это первым).**

1. Базовая механика инференса совпадает: пять ключевых идей Strata/Maya уже
   реализованы в FreeToken (см. таблицу ниже) - переносить нечего.
2. Живых кандидатов два:
   - **KV-кеш в RAM ради слоёв экспертов** (в Strata штатный режим
     `--kv-resident`): главная идея, но для GLM её нет даже в Maya -
     большая кернельная работа из-за DSA-индексера. Решать по офлайн-кривой
     "слоты -> покрытие" - [cases/offline-coverage-curve/TASK.md](../cases/offline-coverage-curve/TASK.md).
   - **Route affinity** (Maya): измерено +22-25% декода ценой KL 0.20
     против точного маршрута; меняет ответы. Дёшево реализуется поверх
     нашего top-8 в hybrid.
3. Не переоткрывать: MTP-спекуляцию (замерено NO-GO на нашей архитектуре),
   KV-квантование (закрыто kv-quant-кампанией), микрофьюжны ниже гейта +5%.

## Что это за движки

Оба движка - C++/ggml-стек на базе llama.cpp, обслуживают по одной архитектуре:

- **Strata** - Qwen3.8-Flash-Next (гибрид: линейное внимание GDN + редкие
  полные QSA-слои, MoE 512 экспертов x top-10, MTP-слой). Архитектурно
  ближайший родственник GLM-5.3-Flash (3:1 KDA/DSA, top-8, MTP).
- **Project Maya** - форк Strata с поддержкой GLM-5.3-Flash, GLM-5.3 (744B),
  DeepSeek-V4.1-Flash и MiniMax; для GLM-5.3-Flash там проведён полный
  компонентный порт-эксперимент (оракул F32, семь семейств кернелов,
  покернельная паритет-проверка).

Модель памяти у обоих одна: **горячие эксперты в VRAM-кеше, все эксперты в
pinned RAM (CPU считает недостающих параллельно с GPU), остальное - с NVMe
во время ответа**. Это тот же контракт, что у нашего hybrid MoE + FTW/session
tier: у нас деление CPU/GPU идёт по парам (слой, эксперт) с LRU-резиденцией
и кап-долей fetch - см. [moe-hybrid-cost-model.md](moe-hybrid-cost-model.md).

## Что совпадает - переносить нечего

| Идея Strata/Maya | Механика у них | Состояние в FreeToken |
|---|---|---|
| Три уровня экспертов (VRAM / RAM / SSD) | VRAM-кеш, pinned RAM, mmap-режимы low-RAM | hybrid MoE + FTW/session tier (RAM/SSD, у пользователя 10/50 GiB) |
| Доля недостающих экспертов: PCIe-фетч vs CPU | `--pcie-frac`, калибруется `--calibrate` | fetch-доля hybrid, авто-резолв на буте по профилю benchbw |
| Стриминг экспертов следующего слоя в префилле | копии перекрыты attention текущего слоя | уже перекрыт: 28.7 мс/шаг копий идут скрыто (nsys, lever2) |
| Преффил копирует только выбранных чанком экспертов | ds4-skip-unpicked: 2.35x на их железе | `copy_missing` фетчит только недостающих; whole-layer - только pageable-ветка |
| Адаптивная резидентность экспертов | decayed-счётчик, swaps каждые N окон, async-вариант | LRU-recency в ensure-experts hybrid, пересчёт каждый шаг |

Профильное бут-зеркалирование тоже есть: `--moe-cache-split profile:...`
(профиль распределения слотов по пулам) и profile-driven fetch-доля. Бут-посев
*каких именно* экспертов резидентны (их `make_profile.py`) у нас не нужен:
LRU прогревается за ~3 шага, а частотная политика как таковая опровергнута
оракулом (R3: oracle 25.7% против LRU 25.1%).

## KV-стриминг: механика Strata и почему для GLM это не копипаст

Механика Strata: `--kv-resident N` держит в VRAM только "самое читаемое" окно
KV (например, 32K ячеек), весь остальной кеш лежит в pinned RAM. Ёмкость
контекста не режется - режется только VRAM-квота, освобождённое идёт в кеш
экспертов. Цена - байты KV в RAM (~13.7 KB RAM на токен контекста у их модели
при 128K). Включается от 64K, когда RAM есть.

Их аргумент за приоритет ёмкости: "каждый лишний GiB VRAM держит ~700
экспертов, и каждый эксперт на GPU - это тот, который CPU не считает". На их
измерениях это читается через фонд слотов: 2x RTX 3080 20 GB, UD-Q4_K_XL,
layer_split 23, parallel 2 - 92.1% пар обслужено из VRAM и 89.2 tok/s против
69.5 tok/s при кеше, замороженном с профиля, и 45.2 tok/s без адаптации
(их машина, их конфиг).

Почему нельзя скопировать для GLM-5.3-Flash: полное внимание здесь - sparse
MLA с DSA-индексером, который на каждом шаге декода сканирует всю историю
(top-2048 позиций по всей длине). Отдать в RAM хвост истории - значит
гather'ить ячейки KV через PCIe внутри attention-кёрнела. **Maya это для GLM
не сделал** - в их документации прямо сказано, что KV-streaming для GLM-5.3
(744B) ещё не обслуживается; у Flash Maya вообще держит контекст в RAM,
но тот кеш мал на их рабочих длинах. То есть рычаг не решён даже теми, кто
уже портировал нашу архитектуру.

Оценка потенциала (оценка, не измерение): при `--kv-reserve-tokens 800000`
и fp8-KV квота KV - порядка нескольких GiB; перенос половины давал бы
~2-3 GiB, т.е. ~+200-300 слотов к текущим ~1.1 тыс. (слот Q3_K_XL ~10.9 MiB,
пул ~1059-1167 слотов на 12096 пар - якоря кампании на конфиге 0.82/400k,
текущий конфиг 0.81/800k надо пересчитать по бут-логу). При покрытие горячего
окна 64k ~0.50 направление в принципе осмысленное, но выигрыш обязан пройти
офлайн-оценку до любой кернельной работы - урок кампаний 2026-09-26, где
бенч-прикидки (оффлоад gather-gap, "26.9 GB/s эффективных") разбились
об инструментировку.

## Route affinity (Maya) - самый дешёвый измеренный рычаг

Механика: в скор выбора маршрутизатора добавляется бонус экспертам, уже
резидентным в VRAM (вес выбранного эксперта остаётся его собственной
вероятностью - меняется только сам выбор top-8). Больше токеновых экспертов
оказывается уже в VRAM, меньше читается из RAM/SSD. Только декод.

Измерено в Maya на GLM-5.3 (744B), Maya-XS, greedy:

| affinity | эффект | цена |
|---|---|---|
| 0.2 | +22-25% к декоду | KL 0.20 против точного маршрута |
| 0.05 | +7-11% | KL 0.15 |
| 0.5 и выше | дальше - эхо промпта | - |

Это меняет ответы - классический knob "скорость vs качество". Для нас:
реализация тривиальна поверх топ-к в hybrid-пути, эффект направлен ровно в
наш ресурс - покрытие слот-пула. Мерить отдельной рукой с env-флагом + батарея
качества. Важно: route affinity смещает сам роутинг, поэтому офлайн-кривая по
трейсу прод его НЕ покрывает (трейс снимают с неаффинити-маршрутизатора).

## Что НЕ переносить (уже закрыто у нас)

- **MTP-спекуляция** - флагман Strata (1.6-1.8x на их модели): у них окно
  верификации из T токенов амортизирует чтение экспертов (лишний токен в окне
  стоит ~60% цены целого эксперта - их замер на RTX 2080 Ti, IQ3_S).
  У нас verify M позиций почти линейно размножает уникальные мисс-пары на
  CPU-ноге - случай закрыт NO-GO замерами W0/W0.5/W1
  (см. [cases/glm53flash-spec-decode/TASK.md](../cases/glm53flash-spec-decode/TASK.md)).
- **KV-квантование как источник VRAM**: у Strata есть k8v4 (ключи 8 бит,
  значения 4 бита с Hadamard-поворотом, -23% против int8) - но у нас
  kv-quant-кампания уже закрыта: скорость плоская, NIAH 60/60 во всех режимах,
  fp8 - sweet spot.
- **Ниже гейта принятия +5%**: CUDA-graph захват KDA-слоёв в Maya (+2.35%
  на их RTX 4090D-риге), EXPDEC-кернел Strata (+1.1% e2e), batched DMA
  (измеренного выигрыша нет). Пропустить.

## Методологические уроки

- Их декларируемый приоритет "больше VRAM важнее более быстрого GPU" -
  структурно совпадает с нашей моделью стоимости: шаг декода гибрида - это
  CPU-нога, объём которой задаёт fetch (см. [moe-hybrid-cost-model.md](moe-hybrid-cost-model.md)).
  Расхождение по MTP объясняется именно этим: у них амортизация окна работает,
  у нас масштабируется CPU-нога.
- Их измерения адаптивного тира (89.2 против 69.5 и 45.2 tok/s, таблица выше)
  - про ЁМКОСТЬ и прогрев резидентности, а не про политику выбора: наш R3-вердикт
  (частотная LRU не лучше timestamp-LRU) и их результаты не противоречат друг другу.
- Их ловушка `FILE_FLAG_RANDOM_ACCESS` (маппинг экспертов падал до 1.93 GB/s -
  дисковая скорость, в 14 раз хуже, потому что подсказка заставляет кеш ОС
  сбрасывать страницы) - урок "подсказки random access - враг удержания".
  Для наших FTW-банков неактуально, но помнить при будущих mmap-путях.

## Как измерить

Гейт для KV-стриминга и любых ёмкостных рычагов - офлайн-кривая
"слоты -> покрытие" из трейса маршрутизации, без запуска сервера и без GPU:
[cases/offline-coverage-curve/TASK.md](../cases/offline-coverage-curve/TASK.md).
План покрывает: аудит существующей телеметрии выбора экспертов, сбор трейса
на исследовательском boot, офлайн-симулятор политики резидентности, sweep
числа слотов и валидацию точки против телеметрии прод. Route affinity этим
экспериментом не покрывается (он смещает сам роутинг) - мерить отдельной рукой.
