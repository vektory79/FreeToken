# Текстовые выжимки nsys-профилей (reports/)

Здесь живут текстовые дестиляции тяжёлых nsys-профилей кампаний оптимизации
GGUF-префилла: по каждой кампании - таблицы суммарного GPU-времени и числа
запусков по ядрам, извлечённые из `nsys export --type sqlite`-дампов (запросы
по таблице `CUPTI_ACTIVITY_KIND_KERNEL`, стандартная схема nsys sqlite).
Методика снятия и интерпретации описана в
[methods/step0-profile.md](../methods/step0-profile.md) и
[methods/step0-profile-mmq.md](../methods/step0-profile-mmq.md) - здесь метод
не выводится заново, фиксируются только измеренные агрегаты.

## Состав

- [dense-q80-profiles.md](dense-q80-profiles.md) - dense q8_0 GEMM: step-0-захват
  (`denseq80`) + свип плотного m-tile (`mtile4/4b/8/16/32/64`) + свип N-split
  (`nsplit1/2`). 9 таблиц профилей + сводная таблица масштабирования.
- [mmq-profiles.md](mmq-profiles.md) - MMQ-префилл: базовый step-0 (`step0`),
  v2-пробы (`v2probe2`), битые захваты (`report2`, `v2probe`), сырьё без пары
  (`report1`, `report3`). 3 таблицы профилей.
- [mmq-v3-profiles.md](mmq-v3-profiles.md) - v3a-проба m-tile=16 против v2
  tile-4 базлайна (`v3aprobe`). 1 таблица профиля.

## Что с сырьём

Бинарные профили (`.sqlite`, `.nsys-rep`) удалены из базы после дистилляции
(решение пользователя: потеря приемлема, оригиналы хранились в рабочих
каталогах кампаний на рабочей машине, вне репозитория). После чистого клона
эти отчёты - единственный след профилей: всё измеренное здесь восстановить из
репозитория нельзя, добавить числа сюда можно только новым прогоном.

## Как читать таблицы

Каждая таблица профиля: топ-5 ядер по суммарному GPU-времени за окно захвата
(launches - число запусков, total - суммарные секунды ядра в окне, mean -
среднее на запуск в мс). Производные «на чанк» значения нормированы делением
окна на медианное время полного чанка из соответствующего A/B-прогона
(ссылки на базлайны даны рядом) и совпадают с вердиктами кампаний в
[topics/prefill-throughput.md](../topics/prefill-throughput.md) и
[topics/moe-hybrid-cost-model.md](../topics/moe-hybrid-cost-model.md).
