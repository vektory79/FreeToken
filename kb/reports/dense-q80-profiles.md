# Профили dense q8_0 GEMM: denseq80, mtile4/4b/8/16/32/64, nsplit1/2

Методика снятия и разбора - [../methods/step0-profile.md](../methods/step0-profile.md),
A/B-протоколы свипов - [../methods/ab-mtile.md](../methods/ab-mtile.md) и
[../methods/ab-nsplit.md](../methods/ab-nsplit.md). Все захваты: nsys,
`--trace=cuda --cuda-graph-trace=node`, окно ~4 чанк-эквивалента стеди-префилла
филлера 65,585 токенов (8128-токенные чанки), окружение - winner-флаги кампании.

## Вердикты по семейству

- Плотный m-tile (knob `FREETOKEN_GGUF_DENSE_MTILE`): среднее время запуска
  `mul_mat_q8_0` падает 15.81 -> 3.96 мс (tile 4 -> 64, ~4x), а плотный терм на
  чанк - 5.52 -> 1.39 с. Согласуется с e2e-свитчем 563.90 -> 792.08 tok/s
  (данные свипа: [../baselines/dense-q80-gemm/ab-mtile-results.json](../baselines/dense-q80-gemm/ab-mtile-results.json)).
- Свип подтверждает вердикт step-0: ядро ALU/issue-зависимо, не BW-зависимо -
  время масштабируется вместе с шириной тайла (меньше пере-чтений на MAC),
  при этом grouped-MoE терм и терм копий банков инвариантны к тайлу
  (4.3-4.4 с и ~3.1 с на чанк во всех захватах).
- N-split (knob `FREETOKEN_GGUF_KDA_NSPLIT`): `nsplit2` режет плотный терм с
  6.10 до 5.53 с на чанк (-0.57 с, возврат ~89% избытка L2 у `kda_in_proj`),
  согласуется с e2e 547.24 -> 561.50 tok/s
  ([../baselines/dense-q80-gemm/ab-nsplit-results.json](../baselines/dense-q80-gemm/ab-nsplit-results.json)).
- Дискриминатор `mtile4b` (явный `=4`) воспроизводит `mtile4` в пределах 0.35%
  по всем термам - sweep-загрязнение чужим сервисом на этом боксе было <0.5%.

Нормировка «на чанк» = окно захвата / T, где T - медианное время полного
чанка соответствующего прогона: denseq80 T=14.87 с (546.58 tok/s),
mtile4/4b 14.414 с (563.90), mtile8 12.348 с (658.45), mtile16 11.189 с
(726.37), mtile32 10.557 с (769.95), mtile64 10.261 с (792.08), nsplit1
14.852 с (547.24), nsplit2 14.473 с (561.50). Все прогоны свипов шли с
дефолтами NSPLIT=2 и MOE_MTILE=32, менялся только плотный тайл; denseq80 и
пара nsplit - плотный тайл 4. Машиночитаемые прогонные метаданные каждого
захвата: [../baselines/dense-q80-gemm/](../baselines/dense-q80-gemm/) (`*_run.json`).

## Сырьё

Бинарные профили этого семейства (denseq80, mtile4/4b/8/16/32/64, nsplit1/2 -
каждый в паре `.sqlite` + `.nsys-rep`) удалены из базы после дистилляции:
таблицы выше покрывают верхнюю часть распределения по времени ядер; полные
56-57 тыс. записей на захват не сохранены (решение пользователя, потеря
принята; оригиналы были в рабочих каталогах кампаний на рабочей машине,
вне репозитория). Дополнительные числовые ряды свипов - в
[../baselines/dense-q80-gemm/](../baselines/dense-q80-gemm/).
