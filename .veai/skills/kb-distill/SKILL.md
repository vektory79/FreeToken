# Дистилляция инсайтов сессии в kb/ (рефлексия)

Ты пополняешь базу знаний `kb/` результатами текущей сессии: превращаешь сырые
факты (правки кода, логи, измерения, решения пользователя) в самодостаточные
статьи и обновления индексов. Ты НЕ удаляешь и НЕ переписываешь историю kb.

## Критические ограничения

- Работай ТОЛЬКО внутри `kb/` (создание/правка md, индексы). Код, тесты и
  `.tasks/` не трогай. Коммиты не делаются - их делает оркестратор по явной
  просьбе пользователя.
- ЗАПРЕЩЕНО удалять файлы kb/ и массово переписывать чужие статьи: этот навык
  только добавляет и точечно обновляет. Чистка/удаления - отдельный триаж с
  утверждением пользователя (прецедент: .tasks/kb-rework/TRIAGE-SUMMARY.md).
- Правила авторинга kb/ обязательны (см. kb/README.md): YAML-шапка
  (title/date/hardware/commits/status/tags) для новых статей; новые
  пояснительные тексты - по-русски, унаследованные артефакты - на английском;
  все кросс-ссылки - только markdown-ссылки [текст](путь) на реально
  существующие файлы; никаких путей вне репозитория (.tasks/, .veai/,
  абсолютных путей машины); одна тема = одна статья <=~250 строк; каждое
  число - только вместе с конфигом, при котором оно измерено.
- Ничего не выдумывай: в kb попадают только факты, подтверждённые в сессии
  (выводы инструментов, измерения, коммиты, утверждения пользователя).
  Непроверенная гипотеза помечается как гипотеза с источником.
- Секреты, токены, абсолютные локальные пути с именами пользователя - не
  записывать; заменять плейсхолдерами.

## Входные данные

Разреши перед началом:
- Объём рефлексии: вся сессия, одна волна, одна кампания или один артефакт.
- Источники: коммиты (`git log` с начала работы), диффы, артефакты в рабочей
  папке (.tasks/<кампания>/), отчёты субагентов, решения пользователя.
- Если источник пуст (нечего дистиллировать) - верни дайджест "0 инсайтов" и
  остановись.

## Алгоритм

1. **Собери кандидатов.** Пройди источники и составь список инсайтов, каждый в
   одной строке: [тип] суть + доказательство (путь/коммит/измерение). Типы:
   root-cause, измеренное число, методика, готч харнесса/теста, исход
   инцидента, решение пользователя, шаблон/процесс.
2. **Отбери.** Критерий включения: факт пригодится будущей сессии и его нельзя
   восстановить за секунды чтением кода. Мимолётное состояние задачи,
   промежуточные числа без вывода, дубли Memory Bank - не включать. Спорные -
   включить в дайджест как "кандидаты без записи".
3. **Найди дом для каждого.** Для каждого инсайта: grep/kb-индекс - есть ли уже
   статья на эту тему.
   - Если есть -> точечное обновление существующей статьи (новый абзац/строка
     в таблице, обновление статуса в шапке; не переписывать чужой текст целиком).
   - Если нет -> новая статья в kb/topics/ (тема) либо профильный раздел:
     kb/methods/ (как измерять), kb/harness/ (новый харнесс -> карточка),
     kb/incidents/ (сбой + root-cause), kb/cases/ (кампания-прецедент),
     kb/findings/ (карта кода/upstream),
     kb/baselines/ (сырые результаты), kb/reports/ (дистиллят сырого профиля).
   - Если инсайтов одного раздела много (>5) и они однородны - делегируй
     черновики субагентам (call_code_agent): один субагент на раздел, каждому
     передай: правило шапки/ссылок, точный список инсайтов с доказательствами,
     требуемый формат результата (дайджест + пути записанных файлов).
4. **Запиши и свяжи.** Напиши статьи/правки; добавь строку в README своего
   раздела и, если тема крупная, в индекс kb/topics/README.md; новые термины -
   в kb/glossary.md. Прогони ДВЕ механические проверки и приложи их вывод к
   дайджесту:
   - таблицы: запусти приложенный к навыку линтер `table_lint.py` из корня
     репозитория (`python3 .veai/skills/kb-distill/table_lint.py kb`) - он
     ловит разрывы таблиц пустыми строками и несовпадение числа колонок
     (учитывая экранированные пайпы `\|`). Код возврата 1 = есть проблемы,
     их надо исправить до закрытия шага. После правок kb/ перезапусти.
   - ссылки: напиши короткий одноразовый скрипт (python), который проверяет,
     что каждая markdown-ссылка резолвится относительно файла, и запусти его -
     битых быть не должно.
5. **Хук в Memory Bank (если доступен).** Если у тебя есть инструменты памяти -
   обнови/создай запись-указатель на новое содержимое (type: project,
   описание-хук <=120 символов). Если доступа нет - верни в дайджесте готовый
   текст хука для оркестратора.
6. **Отчитайся.** Дайджест: список записанных файлов (пути), по каждому - 1
   строка сути; список инсайтов "без записи" с причиной; список кандидатов
   на решение пользователя. Без вставки полных текстов статей.

## Формат вывода

- Дайджест в report_result/ответе: записанное (путь -> 1 строка сути),
  пропущенное (инсайт -> причина), кандидаты на решение пользователя,
  результат проверок (таблицы: линтер 0 проблем; ссылки: проверено N, битых 0).

## Приёмочный чек-лист

- [ ] Ни один файл kb/ не удалён; правки существующих статей точечные.
- [ ] Все новые статьи имеют YAML-шапку; язык: русский для новых текстов.
- [ ] Проверка ссылок: 0 битых markdown-ссылок.
- [ ] Линтер таблиц `table_lint.py`: 0 проблем (разрывы пустыми строками,
  несовпадение колонок, неэкранированные пайпы внутри ячеек).
- [ ] Нет путей вне репозитория и нет секретов/абсолютных локальных путей.
- [ ] Каждое записанное число сопровождено конфигом измерения.
- [ ] Индексы (README раздела, glossary при новых терминах) обновлены.
- [ ] Дайджест содержит пропущенное и кандидатов, а не только записанное.
